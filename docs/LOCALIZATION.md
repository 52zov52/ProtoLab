# Локализация (RU / EN)

Документ описывает, как в ProtoLab устроен выбор языка и переводы, как добавить
новый язык и как проверяется, что ничего не осталось непереведённым.

## 1. Принцип: ключ — это сама английская строка

Перевод не использует искусственные ключи вида `captures.empty.title`. Вместо
этого ключом служит исходная английская фраза:

```tsx
const { t } = useI18n();
return <p>{t("No captures yet")}</p>;
```

Почему так:

* **Английский — тождественный перевод.** Если для строки ещё нет русского
  перевода, интерфейс покажет читаемый английский текст, а не `captures.empty`
  и не пустую строку. Незавершённый перевод деградирует корректно.
* **Нет рассинхронизации ключа и текста.** Нельзя переименовать ключ и забыть
  текст: это одна и та же строка.
* **Читаемые диффы.** В патче видно, какой именно текст переведён.

## 2. Файлы

| Файл | Роль |
|---|---|
| `frontend/lib/i18n.tsx` | Контекст `LocaleProvider`, функции `translate`, `useI18n`, `useT`, константа `LOCALE_STORAGE_KEY`. |
| `frontend/lib/i18n/ru.ts` | Русский каталог `RU_MESSAGES` (оболочка, общие компоненты, граф, потоки, настройки). |
| `frontend/lib/i18n/locales/*.ts` | Фрагменты каталога по страницам (`pagesA`, `pagesB`, `pagesC`), которые `ru.ts` подмешивает через спред. |
| `frontend/lib/format.ts` | Форматирование чисел, дат, длительностей и единиц с учётом локали. |
| `frontend/components/topbar.tsx` | Переключатель `RU`/`EN` (`LocaleSwitcher`). |
| `frontend/tests/i18n.test.tsx` | Тесты выбора языка и полноты перевода. |

## 3. Использование

```tsx
import { useI18n } from "@/lib/i18n";

export function Panel() {
  const { t, locale } = useI18n();
  return <button>{t("Retry")}</button>;
}
```

Подстановка параметров (никакой конкатенации строк):

```tsx
t("Packet #{index}", { index: n })          // «Пакет №7»
t("Show {count} rows", { count: rows.length })
```

Плейсхолдеры — `{имя}`. Если параметра нет, плейсхолдер остаётся как есть.

### Что переводить, а что нет

**Переводим:** подписи кнопок, заголовки и описания панелей, тексты пустых и
ошибочных состояний, `placeholder`/`title`/`aria-label`, заголовки таблиц,
сообщения об успехе.

**Не переводим (это данные, а не интерфейс):**

* значения, приходящие с бэкенда, отображаемые как есть (`{error}`, `{warning}`,
  `String(x)`, коды статусов, идентификаторы протоколов `http1`/`tls`, hex,
  адреса, содержимое `JSON.stringify`);
* имена CSS-классов, `id`, `href`, `key`, имена переменных.

Если подпись вычисляется из константы (например, `columnClassMeta(x).label`),
её переводят в момент отрисовки: `t(meta.label)`.

## 4. Выбор языка и его сохранение

1. При старте приложение рендерится по-английски, чтобы разметка сервера и
   клиента совпала (нет расхождения гидратации).
2. В эффекте язык выбирается в порядке: сохранённое значение `mplab.locale` →
   язык браузера (`navigator.language`, если начинается на `ru`) → `en`.
3. Выбранный язык пишется в `localStorage` под ключом `mplab.locale` и в атрибут
   `document.documentElement.lang`.

Переключатель `RU` / `EN` находится в верхней панели справа.

## 5. Форматирование с учётом локали

`frontend/lib/format.ts` хранит «активную» локаль (`setActiveLocale`) — её
выставляет `LocaleProvider`. Форматтеры используют `en-US` для английского и
`ru-RU` для русского:

| Функция | EN | RU |
|---|---|---|
| `formatNumber` | `12,345` | `12 345` |
| `formatBytes` | `1.5 MiB` | `1,5 МиБ` |
| `formatDuration` | `1.250 s` | `1,250 с` |
| `formatPercent` | `12.3%` | `12,3 %` |
| `formatTimestamp` | ISO-подобный | локальные дата и время |

Английское поведение намеренно сохранено без изменений, чтобы существующие
тесты оставались детерминированными.

## 6. Как добавить строку

1. Оберните английский текст в `t("…")` в компоненте или на странице.
2. Добавьте ключ в `frontend/lib/i18n/ru.ts` или в подходящий фрагмент
   `frontend/lib/i18n/locales/*.ts` с корректным русским переводом.

```ts
// lib/i18n/ru.ts
"Reconstructed bytes": "Пересобранные байты",
```

Если строка должна остаться одинаковой в обоих языках (единица измерения,
название продукта), всё равно добавьте запись-тождество.

## 7. Как добавить новый язык (например, `de`)

1. Создайте `frontend/lib/i18n/de.ts` с `DE_MESSAGES: Record<string, string>`,
   скопировав структуру `ru.ts`.
2. В `lib/i18n.tsx` добавьте `"de"` в тип `Locale`, в `INTL_TAG`, выберите
   каталог в `translate` и дополните `LocaleSwitcher`.
3. В `lib/format.ts` добавьте немецкие единицы и тег `Intl`.
4. Расширьте тест покрытия — он уже опирается на выбранный каталог.

## 8. Проверки

`frontend/tests/i18n.test.tsx`:

* **Выбор языка** — переключение на русский меняет текст, атрибут `<html lang>`
  и запись в `localStorage`; сохранённая настройка применяется при загрузке.
* **Полнота перевода** — тест читает исходники в `app/` и `components/`,
  находит каждый литерал `t("…")` и требует для него запись в `RU_MESSAGES`.
  Так строка не может «молча» остаться английской.

## 9. Ограничения

* Значения-идентификаторы с бэкенда (статусы, коды протоколов) показываются как
  есть и в русском интерфейсе. Это осознанно: это данные, а не подписи; их
  локализация потребовала бы словаря соответствий и не должна искажать
  машинные значения.
* Строки, собранные во время выполнения (динамические), проверкой покрытия не
  ловятся — их нужно переводить через `t(переменная)` вручную.

# Технологии проекта

Документ перечисляет только то, что действительно подключено и используется. Каждая
позиция проверена по исходному коду и файлам зависимостей, а не по памяти: если
библиотека стоит в `package.json`, но не импортируется, здесь она помечена как
неиспользуемая.

Проверено: backend 435 тестов, frontend 196 тестов, CI зелёный на коммите `582904d`.

### Разбор протоколов

Это ядро проекта, и оно написано **самостоятельно на стандартной библиотеке** —
без tshark, Scapy и dpkt:

| Технология | Где |
|---|---|
| `struct` | разбор заголовков pcap/pcapng, длина префикса, порядок байт |
| Собственный потоковый ридер | `analyzers/capture_reader.py` — libpcap и pcapng |
| Собственная сборка TCP-потока | `analyzers/tcp_reassembly.py` |
| Собственный детектор протоколов | `analyzers/protocol_detection.py` |
| Собственная запись pcapng | `analyzers/pcapng_writer.py` |

Причина: анализатор должен показывать байты, из которых сделан вывод, и не
зависеть от того, установлен ли Wireshark на машине аналитика.

## 3. Инфраструктура

|---|---|

`security_opt: no-new-privileges`, `tmpfs` для `/tmp`, порты только на
`127.0.0.1`.

### Опционально

| Технология | Роль |
|---|---|
| **Ollama** | локальная модель для narration. Запускается только профилем `docker compose --profile ai up`, по умолчанию выключен |

### Не используется

Чтобы не считать технологией то, чего в проекте нет:

- **PostgreSQL, Redis** — объявлялись в ранней версии compose, удалены как
  неиспользуемые
- **tshark / Wireshark** — не зависимость. Приложение читает захваты само;
  tshark проверяется через `shutil.which` только чтобы сообщить, доступен ли он
  как внешняя сверка
- **Scapy, dpkt** — разбор PCAP написан вручную
- **Celery, Redis-очереди** — нет фоновых задач
- **Kubernetes, Helm** — нет; развёртывание локальное, одним compose
- **Tailwind UI / shadcn/ui** — своя компонентная база

# Обновление установки (backup → upgrade → verify)

Локальное развёртывание хранит всё состояние в двух местах:

| Что | Где | Что будет потеряно |
|---|---|---|
| База данных | `MPLAB_DATA_DIR/mplab.db` (+ `-wal`, `-shm`) | проекты, захваты, пакеты, гипотезы, интерпретации, отчёты, аудит |
| Артефакты | `MPLAB_DATA_DIR/storage/<project_id>/…` | исходные файлы захватов, потоки, отчёты, PCAPNG-экспорты |
| Архив `.mplab` | куда сохранён оператор | портативная копия проекта (см. `docs/PROJECT_FORMAT.md`) |

В Docker Compose и то и другое — именованный том `mplab-data`.

## 0. Что считается совместимым

Схема версионируется Alembic'ом (см. `docs/TESTING.md` → Migrations). Ревизия
текущей schema — `0001`. Если в вашей установке `alembic current` не показывает
ревизию, база создана более ранней сборкой; при первом старте новый код **штампует**
её как `0001`, не переигрывая миграцию (переигрывание упало бы на первых же
существующих таблицах). Данные при этом не меняются.

## 1. Backup

Пока приложение остановлено:

```bash
# Локальный запуск
docker compose stop backend frontend      # или остановите процессы

# Том Docker
docker run --rm -v madrigal-protocol-lab_mplab-data:/data \
  -v "%CD%:/backup" alpine \
  tar czf /backup/mplab-data-<дата>.tar.gz -C /data .
```

Дополнительно — переносимый архив каждого проекта через UI (**Экспорт** в верхней
панели) или `GET /api/projects/{id}/export`. `.mplab` — это тот же проект в
одном файле с контрольными суммами, поэтому его можно перечитать на другой
машине и другой версией схемы.

> SQLite-файл копируется вместе с `-wal`/`-shm`, иначе последние коммиты,
> ещё не слитые из журнала, потеряются.

## 2. Upgrade

```bash
docker compose up -d --build          # пересобрать образы и поднять стек
docker compose ps                     # оба контейнера healthy

# ревизия схемы после миграции
docker compose exec backend python -m alembic current
```

При старте бэкенд сам выполняет `create_all` (совместимость) и `alembic upgrade
head`. Если оператор ведёт миграции вручную, запустите с
`MPLAB_AUTO_CREATE_SCHEMA=false` — тогда приложение только применяет то, что
есть, и не создаёт схему за вас.

Откат: `docker compose exec backend python -m alembic downgrade -1`, затем
восстановить бэкап из шага 1.

## 3. Verify

```bash
# 1. Здоровье и ревизия
curl http://127.0.0.1:8010/api/health
docker compose exec backend python -m alembic current     # 0001 (head)

# 2. Проекты и целостность захватов — в UI «Обзор» и «Настройки проекта»
curl http://127.0.0.1:8010/api/projects

# 3. Сквозной сценарий (17 шагов) на поднятом стеке
python scripts/demo_scenario.py
```

Проверьте руками то, что нельзя вывести из HTTP-кода: открыть проект, импортировать
захват, построить поток, сформировать отчёт. Все ли проекты на месте, совпадают ли
SHA-256 в панели целостности, не появились ли в Security Center непроверенные
(`unknown`) пункты — именно они сигнализиют, что окружение после обновления
отличается от того, на котором проверка проходила.

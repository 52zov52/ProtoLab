# Брифинг к защите — Madrigal Protocol Lab

Всё, что нужно знать, чтобы ответить на любой вопрос. Проверено по коду и по
живому стеку.

---

## 1. Суть за 30 секунд

> Локальная лаборатория, которая превращает сырой сетевой трафик в **проверяемую**
> спецификацию протокола. Не угадывает, а проверяет: правило применяется к корпусу
> захватов и либо выдерживает каждое сообщение, либо выдаёт контрпример с
> конкретным байтом.

Ключевая фраза, ради которой всё затевалось: **ошибка в гипотезе про байты снаружи
выглядит как успех**. Любая догадка протокола выдаёт за правильную почти всё
подряд. Наша система это ломает.

Противопоставление Wireshark: он показывает то, что **уже знает** о протоколе.
Мы работаем с теми, о которых **никто ничего не знает**.

## 3. Как это работает — пайплайн из 4 шагов

```
1. ИМПОРТ       → потоковый парсер PCAP/pcapng, защита от поддельных длин
2. РЕКОНСТРУКЦИЯ → сборка пакетов в сессии и потоки, разрешение конфликтов
3. АНАЛИЗ       → кадрирование (framing), выравнивание смещений, статистика
4. ВЕРИФИКАЦИЯ   → применяем правило к НОВОМУ корпусу, получаем контрпримеры
```

**Шаги 1–3 дают гипотезу. Только шаг 4 даёт уверенность.** Если спросят «в чём
суть» — отвечать отсюда.

Формат кадрирования — то, что превращает поток байт в сообщения. Без него
«сообщение» не существует. 7 методов:

```
fixed_length, length_prefix, delimiter, signature,
header_rule, heuristic, manual
```

## 4. Одиннадцать фич — что есть и что говорить

| # | Фича | Статус | Ключевое |
|---|---|---|---|
| 1 | TCP: реконструкция + диаграмма состояний | ✅ | Своя сборка, разрешение конфликтов |
| 2 | JA3 / JA3S | ⚠️ | Хэши полные, **база — 4 записи** |
| 3 | Diff двух PCAP | ✅ | Тепловая карта, поиск новых хостов |
| 4 | Расшифровка TLS по SSLKEYLOGFILE | ✅ | 1.2 и 1.3, AES-GCM/CBC, ChaCha20 |
| 5 | Определение протокола | ✅ | 8 детекторов, **не по порту** |
| 6 | Граф взаимодействий | ✅ | Центральность, междуness |
| 7 | NL-поиск по пакетам | ⚠️ | **Детерминированный**, не LLM |
| 8 | Реверс неизвестного протокола | ✅ | Авто-кандидаты + контрпримеры |
| 9 | ML-детектор аномалий | ✅ | Isolation Forest **или** MAD-профиль |
| 10 | AI-отчёт | ⚠️ | Отчёт **из фактов**, не генеративный текст |
| 11 | Экспорт PCAPNG с комментариями | ✅ | Option code 1, IDB, проверка чтением |

### Что говорить по ⚠️ — заранее, не ждать вопроса

**№2, база JA3:** *«Хэш считается по полной спецификации — версия, шифры,
расширения, кривые, форматы точек. Но база намеренно маленькая, четыре записи:
Python requests, curl, Go, OpenSSL. Это не оракул вредоносности. Совпадение
значит лишь "этот хэш опубликован для такого семейства клиента". Расширяется
правкой таблицы.»*

**№7:** *«Запрос на естественном языке разбирается детерминированно, шаблонами,
в том числе на русском — "длиннее", "не больше", "энтропия", "кб", числа
прописью. Результат — типизированный план, не SQL и не Python. Это надёжнее
генерации, но это не ChatGPT для PCAP. Называем честно: компилятор запросов.»*

**№10:** *«LLM пишет текст отчёта. Но все числа в отчёте взяты из сохранённых и
доказанных фактов, отказ системы объясняется, а не замалчивается. Генеративного
"обнаружено 3 подозрительные сессии, хост 10.0.0.5..." у нас нет. Это сознательно:
выдуманный абзац опаснее отсутствующего.»*

## 5. Архитектура и почему именно так

### Слои

```
ФРОНТЕНД    Next.js 16 (App Router) · React 19 · TypeScript 5.9 · Tailwind 4
   ↓ Zod-схемы (типы, выведенные компилятором)
БЭКЕНД      Python 3.11+ · FastAPI · Pydantic · SQLAlchemy 2 · SQLite · Alembic
   ↓
ДАННЫЕ      SQLite + файловые артефакты захватов
```

### Решения, за которые будут спрашивать

**Разбор PCAP написан самим — без tshark, Scapy, dpkt.**
Причина: нам нужно показывать байты, из которых сделан вывод. Свой ридер на
`struct`, своя сборка TCP-потока, свой детектор протоколов, своя запись pcapng.
Побочная выгода — не зависим от того, установлен ли Wireshark на машине аналитика.

**SQLite, а не Postgres. Нет Redis.**
Они были в ранней версии compose — и были удалены, потому что код к ним не
подключался. Объявлять базу, с которой приложение не общается, значит заявлять
возможности, которых нет. Комментарий с этим объяснением остался в файле.

**LLM не исполняется.**
Модель получает типизированный план запроса к фиксированному API. Ни SQL, ни
Python из её ответа не генерируются и не исполняются. Это принципиальная позиция,
а не ограничение бюджета.

**Фронтенд говорит с API напрямую.**
Оба порта опубликованы на loopback хоста, поэтому запросы не покидают машину. Нет
прокси-слоя — меньше точек отказа.

### Безопасность (если спросят)

- Слушает **только loopback**, белый список Host/Origin против DNS-rebinding
- Контейнеры: `read_only`, `cap_drop: ALL`, `no-new-privileges`
- Внешние запросы к LLM **выключены по умолчанию**: включает оператор, и даже
  тогда проект отдельно фиксирует согласие
- Наружу уходят только агрегированные обезличенные сводки
- Bandit в CI

## 6. Что на самом деле сильно — и чем это доказать

### Проверяемость вместо догадок

Спецификация — исполняемый JSON. Модель применяет её к корпусу, который видит
впервые, и выдаёт **контрпримеры**: конкретные сообщения, где правило нарушилось.
Риск подгонки под один удачный пакет исключён на уровне инструмента.

### Честность важнее удобства — и это проверяемо

Эти решения можно защитить, потому что за каждым стоит тест:

| Решение | Что делает |
|---|---|
| Недоступная возможность = «недоступно» | Никогда правдоподобная заглушка |
| Пороги обучения у каждого детектора свои | 24 сообщения обучаются, а не падают |
| Если sklearn нет — сообщаем причину | Не выдаём случайный результат |
| Модель на малом корпусе объясняет | «Нужно N данных», а не «недоступно» |
| Дыры в TCP — это дыры | Показываем разрыв, не заполняем нулями |
| Конфликты перекрытий сохраняют оба варианта | Плюс причина конфликта |

### Локализация как инженерная задача, а не как переводчик

API отвечает на английском — это формат провода. Интерфейс полностью
двуязычный. Но английский не проникает в русский UI **даже из prose, который
возвращает API**: все такие фразы собраны в одном модуле, и есть тест, который
падает, если фраза изменилась без перевода.

Плюс русские склонения собственной реализацией, включая случай 11–14.

## 7. Найденные и исправленные баги — сильный материал

Если спросят «а как вы это проверяли», вот реальные находки:

**Шесть страниц нависали навсегда.** `/`, `/tls`, `/sessions`, `/packets`,
`/security`, `/settings` при прямом открытии по ссылке **зависали на «Loading…»**.
Ни ошибки в консоли, ни упавшего запроса, сервер отдавал корректный ответ.
Работали только при переходе по меню — поэтому баг прожил столько, сколько прожил.
Причина: страница, которая не suspend'ится, рендерится сервером в позицию
fallback, и клиент её не заменяет. Исправлено, закрыто тестом на все 16
маршрутов.

**Кнопка «Выполнить» у помощника отправляла запрос и выбрасывала ответ.**
Читала несуществующее поле через приведение типа. Типы молчали, потому что приведение
типа отключает проверку. Добавлен тест, который падает при возврате сломанной
строки.

**500 на списке действий аудита.** Неверная аннотация `dict[str, str]` против
вложенной структуры. Написан тест, который обходит все 47 GET-маршрутов и
запрещает 5xx.

**База JA3 отвергала каждый запрос по первому байту** в обоих языках. Поле называлось
не так, как оно работало.

Два из пяти примеров в документации были мертвы в обоих языках.

## 8. Честные ограничения — называть самому

На защите честный ответ ценится выше попытки его избежать.

| Ограничение | Почему так |
|---|---|
| **Нет авторизации** | Осознанно для локального одиночного инструмента. Для многопользовательского развёртывания нужно добавить |
| **База JA3 — 4 записи** | Не оракул вредоносности, сознательно небольшая |
| **NL-поиск детерминированный** | Надёжнее генерации, но не ChatGPT для PCAP |
| **Отчёт не генеративный** | Числа из фактов, выдуманного текста нет |
| **TLS 1.3 без шифров без AEAD** | Не поддерживаем — и об этом говорим, а не молчим |
| **7 методов кадрирования, не 8** | Проверяемо в `framing.py` |
| **Zod даёт типы, не проверку в рантайме** | Гарантия на этапе компиляции, не в рантайме |

## 9. Экспресс-Q&A

**— Чем отличаетесь от Wireshark?**
Wireshark показывает то, что уже знает о протоколе. Мы работаем с теми, о которых
никто не знает. И принципиально другое: Wireshark скажет «это похоже на HTTP»,
мы дадим правило, применим его к корпусу и покажем, где оно ломается.

**— А если гипотеза неверная?**
Это ожидаемый сценарий, а не провал. Показываем контрпример — сообщение и байт,
на котором правило нарушилось. Пойманная ложная гипотеза стоит больше непроверенной
красивой.

**— Нейросеть используете?**
Да, но не там, где она может навредить. Пишет текст отчёта и переводит вопрос в
типизированный план. SQL и Python не генерируются и не исполняются. Все числа в
отчёте — из сохранённых фактов.

**— Что делает ваш код, чего не делают другие?**
Разбор PCAP, сборку TCP-потока и детектор протоколов мы написали сами. Причина —
показывать байты, из которых сделан вывод, а не доверять чужому парсеру.

**— Чем это проверяется?**
435 тестов бэкенда, 196 фронтенда, плюс `tsc`, eslint и Bandit. Есть тесты на
конкретные дефекты — они падают, если дефект вернуть.

**— Как локализовано?**
API отвечает на английском — формат провода. Интерфейс двуязычный. Все фразы,
которые API возвращает пользователю, собраны в одном модуле, и тест падает, если
фраза изменилась без русского перевода.

**— Безопасность?**
Локальный защищённый режим: loopback, отозванные capabilities, корневая ФС на
чтение. Внешние запросы к LLM выключены по умолчанию. Наружу — только
обезличенные агрегаты.

**— Что бы доделали в первую очередь?**
Авторизацию — единственное, что реально блокирует многопользовательское
развёртывание. Дальше: расширение базы JA3 и корпус из реальных, а не
синтетических захватов.

## 10. Если спросят «что было самым сложным»

Честный ответ — **честность как проектное ограничение**. Не «какой алгоритм
выбрали», а: каждый раз, когда было проще подставить заглушку или заполнить дыру
нулями, мы этого не делали — и на каждый такой случай писали тест, который
запрещает вернуть заглушку обратно. Это дороже в разработке, и именно поэтому
результату можно верить.

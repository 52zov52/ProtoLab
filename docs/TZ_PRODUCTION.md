# ТЗ: доведение Madrigal Protocol Lab до продакшена

Документ предназначен для инженера (или команды), который принимает проект
после хакатона и доводит его до состояния, пригодного к эксплуатации, продаже
или передаче заказчику. Он описывает **что уже сделано**, **что именно осталось
сделать**, **как проверяется приёмка** и **какие решения обязан принять
заказчик** (часть из них меняет объём).

Родственные документы:

- `docs/ROADMAP.md` — история этапов 0–9, текущие статусы функций.
- `docs/LIMITATIONS.md` — честный список того, чего продукт не делает.
- `docs/SECURITY.md`, `docs/THREAT_MODEL.md` — модель угроз и контроли.
- `docs/ARCHITECTURE.md`, `docs/API.md`, `docs/TESTING.md` — внутреннее устройство.

> **Принцип, который нельзя нарушать при доработке.** Продукт построен на
> обещании «ни один вывод не утверждается без доказательства, которое можно
> открыть». Любая новая функция обязана либо честно работать на реальных
> данных, либо явно сообщать «недоступно/не поддержано» и **никогда** не
> показывать правдоподобную заглушку. Это относится и к ИИ-функциям, и к
> дешифрованию, и к ML-оценкам.

## 1. Краткое описание продукта

Локальная (offline-first) лаборатория для реверс-инжиниринга недокументированных
бинарных сетевых протоколов. Пользователь импортирует PCAP/PCAPNG, получает
реконструкцию TCP-потоков, границы сообщений, статистику по байтам,
декларативную спецификацию формата, контрпримеры к ней, отчёт расследования и
экспорт размеченного PCAPNG.

- **Backend:** FastAPI + Pydantic v2 + SQLAlchemy 2 + SQLite (WAL). Python ≥ 3.11.
- **Frontend:** Next.js 16.4 (App Router) + React 19 + TypeScript strict +
  Tailwind v4 + Zod.
- **Развёртывание:** локальный процесс или Docker Compose, оба на loopback.
- **Внешние зависимости в рантайме:** нет. Сеть наружу закрыта по умолчанию.

## 3. Объём работ

### 3.1. Входит (обязательно для продакшена)

1. Воспроизводимая сборка и релиз (пиннинг версий, артефакты, версионирование).
2. Миграции БД (Alembic) + процедура апгрейда/бэкапа.
3. Локализация RU/EN (требование заказчика).
4. Достройка тестового покрытия до §23 + браузерные E2E.
5. Эксплуатационные вещи: структурированные логи, метрики, health, backup/restore,
   политика хранения, шифрование at rest (по решению заказчика).
6. Безопасность зависимостей и парсеров (pip-audit, npm audit, fuzz-тесты).
7. Нагрузочная проверка на целевом контейнере.
8. Пользовательская и администраторская документация.
9. Финальная приёмка по §29/§31.

### 3.2. Входит по решению заказчика (меняет объём)

- **Режим эксплуатации:** только локальный single-user, либо
  многопользовательский серверный режим (тогда обязателен эпик E7).
- **TLS Decryption** (§8.4): делать или оставить честным исключением.
- **Стек UI §4** (Monaco/TanStack/Recharts/D3): приводить к букве ТЗ или
  зафиксировать отклонение.
- **PDF-экспорт**.

### 3.3. Не входит

- Облачный сервис, мобильные приложения, биллинг.
- Поддержка не-TCP протоколов как основного сценария (продукт про TCP-потоки).
- Обучение собственных нейросетей (для №8 по ТЗ модель не требуется).

## 5. Эпики, задачи и приёмка

Формат: **задача → что сделать → критерий приёмки**. Эпики можно делать
параллельно, кроме отмеченных зависимостей.

### E1. Релиз-инжиниринг и упаковка

- **E1.1 Версионирование.** Единая версия продукта в `backend/pyproject.toml`,
  `frontend/package.json`, UI («About»), `/api/health`. Тег `vX.Y.Z`, строка
  сборки.
  - *Приёмка:* `GET /api/health` возвращает версию; версия видна в UI; тег
    совпадает.
- **E1.2 Воспроизводимость Python.** Зафиксировать полный lock-файл
  (`uv.lock` / `poetry.lock` / `pip-tools`), чтобы `pip install` давал те же
  версии, что в тестах. Сейчас `pyproject.toml` пинит верхний уровень, но
  транзитивные зависимости не зафиксированы.
  - *Приёмка:* на чистой машине установка из lock-файла → `pytest` зелёный;
    `pip freeze` воспроизводим.
- **E1.3 Воспроизводимость Node.** `package-lock.json` зафиксирован; `npm ci`
  воспроизводим. Проверить отсутствие расхождения `node_modules` ↔ `package.json`
  (в истории был инцидент — см. ROADMAP §4).
  - *Приёмка:* `npm ci && npm test && npm run build` на чистом клоне → зелёно.
- **E1.4 Верифицировать Docker.** **Реально** выполнить `docker compose up
  --build`, дождаться healthy, прогнать `scripts/live_check.py` против контейнера,
  проверить немонтируемый read-only rootfs и loopback-публикацию.
  - *Приёмка:* зафиксированный прогон в `docs/`; `docker compose config` без
    ошибок; Security Center в контейнере честно отдаёт `unknown` по недоступным
    проверкам.
- **E1.5 Артефакты релиза.** Собрать и опубликовать: образы с digest, архив с
  исходниками, `examples/`, документацию; контрольные суммы.
- **E1.6 CHANGELOG и семвер.** Завести `CHANGELOG.md`, политику версий.

### E2. Миграции БД (Alembic)

- **E2.1 Инициализировать Alembic.** `backend/alembic.ini` + `backend/alembic/`,
  начальная миграция `0001_initial`, режим автогенерации против моделей.
  - *Приёмка:* `alembic upgrade head` на пустой БД создаёт схему, идентичную
    текущей (`create_all`); тест сравнивает.
- **E2.2 Перевести приложение на миграции.** При старте проверять версию схемы;
  старое поведение `create_all` — только для тестов.
- **E2.3 Процедура апгрейда.** Документировать `backup → upgrade → verify` для
  пользовательских данных (SQLite-файл + каталог артефактов + версия схемы в
  архив `.mplab`).
  - *Приёмка:* сценарий апгрейда с «v1-данными» проходит в тесте.

### E3. Локализация RU/EN

- **E3.1 Каркас i18n.** `frontend/lib/i18n.tsx`: словари, `t()`, провайдер,
  переключатель в topbar, сохранение выбора, `<html lang>`, форматирование

- **E4.4 Регрессии.** Сохранить существующий `tests/test_regressions.py` и

### E6. TLS Decryption через `SSLKEYLOGFILE` (решение заказчика)

**Если берём — риск высокий, ТЗ ставит приоритет «дополнительный».**

- **E6.1 Загрузка keylog как недоверенного файла.** Лимиты, парсинг
  `CLIENT_RANDOM <hex> <hex>` и меток TLS 1.3, безопасное хранение
  (owner-only), маскирование в логах/отчётах/ИИ.
- **E6.2 Матчинг ключа к сессии** по `client_random` из Hello.
- **E6.3 Дешифрование** TLS 1.2/1.3 через `cryptography` **или** делегирование
  `tshark`; получить application data; разбор HTTP внутри HTTPS
  (переиспользовать `_detect_http`).
- **E6.4 UI:** раскрытие расшифрованных записей с явной пометкой источника
  (keylog), per-session причина отказа.
- **E6.5 Безопасность:** keylog **не** попадает в `.mplab`, отчёт и контекст ИИ.
- **E6.6 Тесты:** расшифровка тестового TLS-capture с известным keylog;
  security-тест на маскирование секретов.
  - *Приёмка:* в UI виден HTTP-запрос внутри HTTPS; при отсутствии keylog —
  честное «дешифрование не поддерживается».

### E7. Многопользовательский режим (только если заказчик требует сервер)

- **E7.2 Авторизация/RBAC** и проверка доступа к объектам проекта на сервере

### E8. Эксплуатация: наблюдаемость, данные, бэкапы

- **E8.1 Структурированные логи** (JSON), корреляционный ID запроса/задачи,
  redaction-фильтр (уже есть) распространить на все новые пути.
- **E8.2 Метрики.** `/metrics` (Prometheus-совместимые): длительность анализа по

- **E8.3 Health/readiness.** Уже есть `/api/health` — дополнить проверкой БД и

- **E8.4 Backup/Restore.** Документированная процедура и скрипт: остановка

- **E8.5 Retention/GC.** Политика хранения: TTL захватов/артефактов, ручная

- **E8.6 Шифрование at rest** (по решению заказчика): шифрование каталога данных

- **E8.7 Надёжность фоновых задач.** Персистентность очереди, перезапуск после

## 6. Нефункциональные требования

## 7. Критерии готовности к продакшену (Definition of Done)

Продукт считается готовым, когда одновременно выполнено:

1. `python -m pytest backend -q`, `npm test`, `npm run typecheck`, `npm run lint`,
   `npm run build` — зелёные на чистом клоне.
2. `scripts/demo_scenario.py` и `scripts/live_check.py` зелёные против
   **реально запущенного** backend.
3. `docker compose up --build` **фактически проверен**, `live_check` проходит
   против контейнера.
4. Alembic-миграции покрывают схему; сценарий апгрейда проходит.
5. Локализация RU/EN завершена и покрыта тестом.
6. `pip-audit` и `npm audit` не содержат неразобранных критичных находок; SBOM
   сформирован.
7. Fuzz-прогоны парсеров завершились без необработанных падений.
8. Нагрузочный профиль снят на целевом окружении и задокументирован.
9. Backup/restore и retention проверены тестом/скриптом.
10. Документация пользователя и администратора есть; README/API/LIMITATIONS
    соответствуют фактическому поведению.
11. Возможности, объявленные недоступными, честно отображаются (не
    замаскированы); критерии §29/§31 закрыты.
12. Тег релиза собран воспроизводимо из CI, артефакты и контрольные суммы
    опубликованы.

> Если заказчик выбрал **серверный** режим эксплуатации, добавляется E7 целиком,
> иначе продакшен — это «локальная установка».

## 8. Риски и допущения

| Риск | Влияние | Что делать |
|---|---|---|
| Серверный режим без E7 | Утечка неаутентифицированного API | Не публиковать; либо завершить E7 до релиза |
| TLS Decryption (E6) | Высокая сложность, безопасность keylog | Сначала безопасность, потом функция; при нехватке времени — честное исключение |
| SQLite под конкурентной нагрузкой | Блокировки/OOM | WAL уже включён; ограничить конкуренцию задач; рассмотреть PostgreSQL только если реально нужен сервер |
| Смена схемы при апгрейде | Потеря пользовательских данных | E2 + обязательный бэкап |
| Непроверенный Docker | «Работает у меня» | E1.4 — реальный прогон |
| Локализация ИИ-текстов | LLM выдаёт нарратив не на «честном» языке | Шаблоны и промпты — под ревью; никогда не подавать вывод модели как доказательство |
| Зависимости CVE | Компрометация | E9, регулярный пересбор |

## 10. Передача: как запустить и проверить

### 10.1. Окружение

- Python ≥3.11 (проверено на 3.12 и 3.14), Node ≥20.
- Наличие `scikit-learn` включает детектор аномалий; без него эндпоинты честно
  возвращают `503 dependency_unavailable`.
- `tshark` и `pip-audit` опциональны; их отсутствие отображается как `unknown`.

### 10.2. Локальный запуск (без Docker)

```bash
# Backend (из каталога backend)
python -m app                      # слушает 127.0.0.1:8010, docs на /api/docs

# Frontend (второй терминал, из frontend/)
npm ci && npm run dev              # http://127.0.0.1:3000
```

> В исходном README использован путь `.venv/bin/python`. Проверьте, что в вашем
> окружении зависимости установлены именно в том интерпретаторе, которым
> запускаете `-m app` (в переданном окружении `.venv` был пуст, а рабочие
> зависимости стояли в системном Python 3.14).

### 10.3. Проверки

```bash
python -m pytest backend -q                    # 172 теста
cd frontend && npm test && npm run typecheck && npm run lint && npm run build
python scripts/demo_scenario.py                # 17 шагов E2E (in-process)
python scripts/live_check.py                   # E2E против запущенного сервера
```

### 10.4. Docker

```bash
docker compose up --build          # не проверялся фактически — задача E1.4
docker compose --profile ai up     # опциональная локальная Ollama
```

`max_upload_bytes` = 100 МиБ · `max_capture_bytes` = 100 МиБ ·
`max_json_body_bytes` = 2 МиБ · `max_packets_per_capture` = 250 000 ·
`max_tcp_sessions_per_capture` = 1000 · `max_concurrent_jobs` = 4 ·
`max_ai_context_chars` = 24 000 · `max_ai_output_chars` = 8 000 ·

  `column-classes.ts`, `evidence-links.ts`).

  `verify_sample_protocol.py`), `examples/`, `sample_protocol/`,
  `tools/testbench/`.

### 11.4. Известные ограничения (см. `docs/LIMITATIONS.md` для деталей)

TLS Decryption · нет аутентификации · нет шифрования at rest · нет PDF ·
нет Alembic (до E2) · нет локализации (до E3) · нет fuzzing (до E4.3) ·
нет питон-сканирования CVE (до E9.1) · протокол-детекция эвристическая ·
аномальные оценки — не вероятности · граф-хабы — «кандидаты», не C2 ·
совпадение JA3 — не «вредоносность».

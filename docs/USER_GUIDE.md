# Руководство пользователя — Madrigal Protocol Lab

Это практическое руководство по интерфейсу: что делает каждая вкладка, каждая
панель, каждая кнопка и каждое поле, как читать цвета и подписи и в каком
порядке проходить исследование от сырого PCAP до проверяемой спецификации.

Главный принцип приложения: **ни один вывод не утверждается без доказательства,
которое можно открыть**. Поэтому в интерфейсе много бейджей с оговорками — это
не украшение, а часть результата. Если данных не хватает, приложение пишет
«недоступно» / `unknown`, а не показывает правдоподобную заглушку.

---

## 1. Как запустить

Нужны два процесса: API (backend) и интерфейс (frontend).

```bash
# 1. Backend — слушает 127.0.0.1:8010
cd backend && python -m app

# 2. Frontend — слушает 127.0.0.1:3000 (второй терминал)
cd frontend && npm install && npm run dev
```

Откройте <http://127.0.0.1:3000>. Всё работает локально: ни аккаунта, ни
интернет-доступа, ни API-ключа.

Проверить, что backend жив, можно по индикатору в правом верхнем углу
(см. §3) и по адресу <http://127.0.0.1:8010/api/docs> (интерактивная
документация API).

## 2. Главные понятия (глоссарий)

Перед вкладками — словарь. Он же объясняет, почему путь исследования устроен
именно так.

| Термин | Что это |
|---|---|
| **Project** (проект) | Контейнер исследования: список захватов, гипотезы, отчёты. Проектов может быть много. |
| **Capture** (захват) | Один импортированный файл `.pcap`/`.pcapng`/`.cap`. Хранится без изменений, с SHA-256. |
| **Packet** (пакет) | Сырой пакет из захвата (номер, время, адреса, порты, флаги, длина, payload). |
| **TCP session** (сессия) | Одна TCP-беседа (пара адрес:порт ↔ адрес:порт). Повторное использование порта даёт **отдельные** сессии. |
| **Stream** (поток) | Одно направление сессии (A→B или B→A), собранное из сегментов по номерам последовательности. |
| **Message** (сообщение) | Границы внутри потока, найденные по правилу кадрирования (framing). Один TCP-пакет ≠ одно сообщение. |
| **Framing** (кадрирование) | Способ найти, где заканчивается одно сообщение и начинается следующее (по длине, разделителю и т.д.). |
| **Hole / conflict** (пробел / конфликт) | Потерянные байты (пробел) или разные байты в одной позиции (конфликт). Оба показываются явно, нулями не затираются. |
| **Hypothesis** (гипотеза) | Формулировка о формате провода, которую предстоит проверить. |
| **Interpretation** (правило/интерпретация) | Исполняемая декларативная спецификация гипотезы (JSON). |
| **Corpus** (корпус) | Набор захватов, на которых проверяется правило. |
| **Validation run** (прогон проверки) | Результат применения правила к корпусу: сколько сообщений совпало и сколько нет. |
| **Counterexample** (контрпример) | Сообщение, нарушившее правило: какое правило, какие байты, из какого пакета. |
| **JA3 / JA3S** | Отпечатки TLS-рукопожатия клиента/сервера. Нужны для распознавания клиента, ключи не требуются. |
| **Расшифровка TLS** | Открытый текст прикладных записей — только по загруженному ключевому журналу и только для поддерживаемых наборов шифров. |
| **Hub candidate** (кандидат в хабы) | Узел с большим числом связей по фиксированным порогам. Это **кандидат на просмотр**, а не приговор. |
| **Anomaly** (аномалия) | Оценка нетипичности относительно выбранной базы. Не вероятность и не «опасность». |

### 3.1. Левое меню (сайдбар)

| **Hypotheses & Rules** | Спецификации, проверка, контрпримеры |
| **Capture Diff** | Сравнение двух записей с тепловой картой |
| **Network Graph** | Наблюдаемые взаимодействия узлов |

открывается в контексте текущего проекта. Активный раздел подсвечен.

### 3.2. Верхняя панель (TopBar)

Слева направо:

- **Бейдж проекта** — имя текущего проекта (или «no project»).
- **Подпись захвата** — `capture <первые 8 символов>` либо «no capture selected».
  Захват выбирается в разделе Captures и запоминается на время сессии.
- **Поле поиска** (по центру-справа) с подсказкой
  «Search: responses longer than 1000 bytes». Нажмите Enter — запрос уедет в
  **Investigation Assistant** (`/assistant?q=...`).
- **Индикатор backend** — зелёный `backend up` или красный `backend down`
  (опрос `/api/health` каждые 15 секунд). Если красный — интерфейс открыт, но
  данные не подтянутся: запустите backend.
- **Бейдж заданий** `N jobs` со спиннером — появляется, когда в очереди есть
  фоновые задания (например, отложенный анализ захвата).
- **Import .mplab** — импорт проекта из переносимого архива. После импорта
  проект становится текущим, и появляется сообщение вида
  «Imported {...}; N hash mismatch(es)». Ненулевое число несовпадений хэшей —
  важный сигнал: файлы в архиве не совпали с записанными SHA-256.
- **Export** (голубая кнопка) — экспорт проекта в `.mplab`. Появляется
  сообщение «Archive written: <путь> (<байт> bytes)»: архив пишется **на
  сервере**, кнопка не скачивает файл в браузер.

Кнопки «Import»/«Export» показывают ошибки в всплывающем блоке под панелью.

## 4. Сквозной путь исследователя (рекомендуемый порядок)

Это тот же маршрут, что проходит `scripts/demo_scenario.py`:

1. **Overview** → создать проект.
2. **Captures** → импортировать PCAP → **Run analysis**.
3. **TCP Sessions** → посмотреть диаграмму, найти проблемные сессии.
4. **Stream Explorer** → прочитать байты, закрыть пробелы, посмотреть отпечатки TLS,
   применить кадрирование.
5. **Protocol Workbench** → сравнить сообщения, найти кандидатов в поля.
6. **Hypotheses & Rules** → записать спецификацию, проверить на корпусе, прочитать
   контрпримеры.
7. **TLS Analysis / Capture Diff / Network Graph / Anomaly Detection** — по
   необходимости, это вспомогательные инструменты.
8. **Investigation Assistant** → поиск по индексу.
9. **Reports** → собрать отчёт со ссылками.
10. **Security Center / Project Settings** → проверка конфигурации и согласие на ИИ.

Ниже — разбор каждого раздела.

## 5. Overview

Точка входа. Если проект не выбран — показываются пустое состояние и форма
создания проекта.

**Форма проекта (ProjectPicker):**
- Список существующих проектов: имя, число захватов / сообщений / гипотез, бейдж
  `current` у текущего. Клик по проекту делает его текущим; кнопка **Refresh**
  перечитывает список.
- **New project**: поле **Name** (обязательное), поле **Description**, кнопка
  **Create project** (неактивна, пока имя пустое).

**Метрики проекта** (сетка плиток): Captures, Packets, TCP sessions, Streams,
Messages, Bytes on disk, Hypotheses, Interpretations, Validation runs,
Counterexamples (предупреждающий тон, если > 0), Problem sessions (то же),
Anomaly detection (доступно / недоступно).

**Source integrity** — состояние целостности: бейдж «all match» или «mismatch» и
список захватов со статусом. Оговорка поясняет, что SHA-256 подтверждает только
совпадение байт с моментом импорта.

**Analyzer versions in use** — какие версии анализаторов применялись.

**CapturePicker** — выбор захвата; **Research path** — ссылки-шаги 1–6, чтобы не
заблудиться.

Ссылка вида `/?project=<id>` сразу переключает текущий проект.

## 6. Captures

Управление захватами и запуск анализа.

- **Импорт PCAP** (голубая кнопка) — выбор файла `.pcap/.pcapng/.cap`.
- **Project totals** — суммарные счётчики по проекту.
- **Captures in this project** — кликабельный список. Бейдж статуса:
  `completed` (зелёный), `failed` (красный), иначе нейтральный. Клик выбирает
  захват.
- **Панель выбранного захвата**: имя, формат, размер, SHA-256, время импорта,
  статус, и кнопки:
  - **Run analysis** — синхронный анализ (пакеты, сессии, пересборка, потоки).
  - **Queue in background** — тот же анализ фоновым заданием.
  - **Delete** (красная) — удаляет захват и все производные данные (с
    подтверждением).
- **Analysis result** — статистика: сессии, потоки, сообщения, сессии с
  проблемами (предупреждение), диагностика чтения (ошибки/предупреждения),
  примененные опции анализа, оговорка.
- **TCP sessions in this capture** — таблица: Identity, Endpoints, Completeness
  (бейдж `complete` зелёный, иначе предупреждение), Role basis (на основании
  чего определена роль).

Первый захват в списке выбирается автоматически.

## 7. Packets

Таблица пакетов выбранного захвата (виртуализированная — рисуются только
видимые строки).

- **Фильтры**: поле **адрес** (source/destination), выбор **transport**
  (any / TCP / UDP / ICMP / IGMP / other), поле **min payload**. Смена фильтра
  сбрасывает номер страницы.
- Счётчик `N packet(s) · page X/Y` и кнопки **Prev / Next** (по 250 строк).
- **Таблица**: `#`, Time, Source, Destination, Proto, Flags (`0xNN`), Len,
  Payload, State (метка `truncated`, если пакет обрезан).
- Клик по строке открывает **Packet bytes** — hex-дамп байт, как они лежат в
  файле (плотный HexViewer). Панель «No packet selected», пока ничего не
  выбрано; выбор сбрасывается при смене фильтра/страницы.

## 8. TCP Sessions

Диагностика пересборки TCP — здесь видно, что реально наблюдалось на проводе.

**Слева — список сессий**: identity, узлы, длительность, время старта, бейдж
полноты. Клик выбирает сессию.

**Справа — три панели выбранной сессии:**

1. **Observed state diagram** — визуальная временная диаграмма (компонент
   TcpStateDiagram). Две дорожки A→B и B→A; метки окрашены по типу
   (SYN/ACK/DATA/FIN/RST), отдельно помечены аномалии: `R` — повтор,
   `O` — порядок нарушен, `D` — дубликат, `Z` — нулевое окно. Внизу — фазовая
   полоса handshake / data / teardown. Легенда: «R retransmission · O out of
   order · Z zero window». Важно: диаграмма рисует **только присутствующие
   пакеты**; это не реконструкция конечного автомата, отсутствующие пакеты
   оставлены отсутствующими.

2. **Connection state (observed)** — бейджи «SYN/FIN/RST seen», уверенность роли
   (`role_confidence`) и её обоснование (`role_rationale`), оговорка и таблица
   событий: `#`, Time, Dir, Source, Flags, Seq, Ack, Win, Payload, Options.
   Флаги RST красные, SYN зелёные.

3. **Reconstruction diagnostics** — по каждому потоку (направление, политика
   конфликтов) счётчики: retransmissions, exact duplicates, out of order,
   holes (предупреждение), byte conflicts (красный), zero window. Ниже —
   списки пробелов (start..end, причина) и конфликтов (сохранённые/отклонённые
   байты в hex). Раскрывающийся блок «What these labels mean» даёт определения.

## 9. Stream Explorer

Побайтовый разбор одного направления.

Сессия берётся из `?session=` или из текущего workspace. Если сессии нет —
пустое состояние со ссылкой в TCP Sessions.

- **Переключатель потоков** — кнопки по направлениям (`direction · local→remote`,
  present/total байт) и бейдж протокола (метка + уверенность).
- Навигация по окну: шаг **512 байт**, кнопки вперёд/назад, подпись
  `offset N … M`.

**Левая колонка:**
- **Reconstructed bytes** — HexViewer с явными пробелами (GAP) и подсветкой
  выбранного сообщения.
- **Coverage gaps** — появляется при пробелах: диапазоны, причина, оговорка.
- **TLS fingerprints (JA3/JA3S)** — если в потоке есть рукопожатия: kind,
  надёжность (reliable / unreliable), md5, версия, raw, SNI, ALPN, группы,
  причина ненадёжности и трактовка совпадения; оговорка о том, что совпадение —
  не вердикт о безопасности.
- **Framing candidates** — ранжированные кандидаты: score, метод+конфигурация,
  доказательства. У лучшего есть кнопка **Apply and re-frame** — она повторно
  анализирует захват с этим правилом кадрирования.

**Правая колонка:**
- **Framed messages** — таблица: `#`, Range, Len, Declared, State
  (`complete`/`partial`). Клик подсвечивает сообщение в hex.
- **Packets behind the current window** — какие пакеты дали байты текущего окна
  (Packet #, смещения).

## 10. TLS Analysis

Пассивный анализ TLS без ключей.

- **Verdict** — итог: текст вывода и бейджи (отпечатки клиентов, совпадения
  «не-браузер», ненадёжные рукопожатия, просканировано потоков/всего, категории
  browser / library / bot / server / unknown), оговорка и ссылка на справочник
  отпечатков.
- **Fingerprints** — таблица отпечатков с чекбоксом **«only non-browser
  clients»** (фильтр). Колонки: Kind, Fingerprint, Client family (+источник),
  Class, Confidence, Seen (число вхождений и потоков), SNI/ALPN/versions.
- **Финальная оговорка**: совпадение отпечатка — это **не** утверждение о
  человеке или вредоносности.

Если рукопожатий нет — пустое состояние поясняет, что отсутствие отпечатка не
означает «не зашифровано».

### Расшифровка открытыми ключами (если нужен текст внутри TLS)

- **TLS key log** — панель ключевых журналов: кнопка **«Загрузить ключевой
  журнал»** (файл `SSLKEYLOGFILE`), список загруженных (имя, первые 16 символов
  SHA-256, бейджи меток вида `CLIENT_RANDOM: 1`, кнопка **Удалить**), кнопка
  **Обновить**. Содержимое файла интерфейс никогда не показывает; API возвращает
  только метки и количество.
- **Расшифровать поток** — выбор потока (те, где найдены рукопожатия), выбор
  журнала, кнопка **Расшифровать**. Результат: бейджи статусов, число
  расшифрованных байт и таблица записей — `#`, тип записи, статус, открытый
  текст (усечённый фрагмент), причина и набор шифров.

Статусы записей и что они значат:

| Статус | Значение |
|---|---|
| `decrypted` | Аутентификация пройдена: это ровно те байты, которые отправил собеседник |
| `auth_failed` | Тег не сошёлся: ключи не те или байты изменены. Ничего не показывается |
| `unsupported` | Набор шифров или нужного секрета нет. Ничего не показывается |
| `truncated` | Захват обрывается внутри записи |
| `not_encrypted` | Это рукопожатие или alert — они и так читаемы |

Набор шифров берётся из ServerHello этого же диалога (при необходимости — из
соседнего направления) — в поле **Detail** видно, какой именно применялся.
Поддерживаются: TLS 1.2 AES-GCM и AES-CBC+HMAC, TLS 1.3 AES-GCM и
ChaCha20-Poly1305. Остальное сообщается как неподдерживаемое.

## 11. Protocol Workbench

Основной инструмент поиска формата сообщений.

- **Переключатель направлений** — выбор потока (одно направление за раз).
- **Messages (select 2–6 to compare)** — таблица: чекбокс, `#`, Range, Len,
  Entropy, Unique, State. Клик отмечает сообщение; выбирается от 2 до 6 (при
  превышении — вытеснение по FIFO). Кнопка **clear** снимает выбор.
- **Per-offset alignment** — если выбрано ≥ 2 сообщений, показывается
  выравнивание HexComparison: описание, таблица со столбцом Offset и столбцами
  по сообщениям, чекбокс **«only differing offsets»**, отсутствующие байты у
  коротких сообщений показаны как `— absent —`, изменённые строки подсвечены.
- **Field candidates inferred from the bytes** — карточки кандидатов: бейдж
  роли, имя `@ offset (sizeB endianness)`, уверенность %, обоснование,
  supports/contradicts. Оговорка: это гипотезы о форме, а не о смысле.
- **Column statistics** — легенда классов и цветная полоса по смещениям (первые
  64), таблица: Offset, Class (цветной бейдж с подсказкой-обоснованием),
  Present, Absent (предупреждение при > 0), Unique, Entropy, Change rate,
  Most common. Оговорка про отсутствующие байты.

## 12. Hypotheses & Rules

Превращение гипотезы в исполняемое правило и проверка на корпусе.

**Слева:**
- **Hypotheses** — кнопка **new** создаёт черновик (имя через диалог), список с
  бейджем статуса, версией `vN` и датой; выпадающий список статуса
  (draft / proposed / testing / supported / contradicted / revised / rejected).
- **Interpretations** — список правил (имя, `vN`, контрольная сумма). Клик
  выбирает правило.

**Центр — Interpretation specification (JSON):**
- Редактор JSON. Кнопки: **reset** (вернуть стартовую заготовку),
  **create** (создать правило из черновика), **save** (сохранить выбранное).
- Живая проверка JSON: зелёная надпись «Valid JSON…» или красная ошибка разбора.
  Схему всё равно проверяет backend при сохранении.

**Справа:**
- **Validate against a corpus** — **CorpusPicker** (чекбоксы захватов с бейджами
  `analysed`/`not analysed`; кнопка **clear corpus**), кнопка **Run validation**
  (неактивна, если правило не выбрано; ошибка, если корпус пуст). Затем
  **VerdictSummary**: вердикт + счётчики total/matched/partial/failed/unparsed +
  примечания.
- **Validation run** — id прогона, правило, версия правила, контрольная сумма,
  статус, анализатор; предупреждение **stale**, если правило с тех пор менялось.
- **Counterexamples** — список нарушивших сообщений (id, нарушенное правило,
  смещения, причины, раскрываемые альтернативные объяснения) с оговоркой. Пустой
  список означает «все сообщения корпуса удовлетворили правило».
- **What the format can express** — поддерживаемое кадрирование, поддерживаемые
  типы полей, явно неподдерживаемое, оговорка о безопасности.

> Замечание: список корпуса **не** заполняется автоматически — выберите захваты
> вручную. Правило, проверенное на пустом корпусе, ничего не доказывает, поэтому
> backend отказывает.

---

## 13. Capture Diff

Сравнение двух записей с тепловой картой.

- **Comparison setup**: выпадающие поля **Baseline**, **Compare with**, **Focus**
  (all / endpoints / sessions / messages / bytes / diagnostics) и бейдж состояния
  («ready» или «выберите два разных захвата»).
- Когда оба выбраны:
  - **Session heat map** — легенда шкалы похожести 0–1 и пояснение «Δ shade =
    magnitude · blue growth · amber shrink · empty = no change»; таблица: Status,
    Endpoints, Similarity (цветная), Byte Δ, Packet Δ, Why. Клик по строке
    выбирает её, затем кнопки **Open baseline session** / **Open comparison
    session** переносят в TCP Sessions. Оговорка interpretation_note: различие —
    это не аномалия, цвет кодирует величину и направление изменения.
  - **Endpoints** — списки added / removed / common.
  - **Message-level differences** — таблица: Dir, `#`, Status, Base len,
    Compare len, Bytes changed.

## 14. Network Graph

Граф наблюдаемых взаимодействий.

- **Тулбар**: поле **Min traffic** (байты), подпись `N of M endpoints shown · E of
  F interactions`, кнопка **Clear filter** (если фильтр > 0) и оговорка, что
  фильтр только скрывает узлы, но не меняет анализ.
- **Панель графа**: легенда протоколов (по рёбрам), кнопки зума **− / + /
  reset**. Узлы размера по объёму трафика, рёбра окрашены по **определённому
  протоколу** (не по номеру порта) и толщиной по объёму. Кандидаты в хабы
  обведены пунктирным золотым кольцом. Клик по узлу выбирает его; при выборе
  подсвечиваются рёбра. Перетаскивание — панорама, колесо и кнопки — зум,
  двойной клик — сброс. Внизу: узлы/рёбра/байты, число кандидатов в хабы,
  **clear selection**, предупреждения.
- **Справа**: **Node: label** (байты, пиры, degree centrality, betweenness, бейдж
  hub и его причина, список наблюдаемых соединений) и **Centrality ranking**
  (ранг, метка, бейдж hub, deg, betweenness) с оговоркой interpretation_note.

> Бейдж «hub candidate» — это кандидат на ручной просмотр по фиксированным
> порогам, а **не** утверждение о вредоносности или C2.

## 15. Anomaly Detection

Обучение базовой модели и ранжирование нетипичных сообщений/сессий.

- **Train a baseline**: поле **Model name**, выбор **Scope**
  (messages / sessions), кнопка **Train baseline** (неактивна без выбранного
  захвата), список захватов корпуса с их `analysis_status`; уведомления и ошибки.
- **Latest model** — сырой JSON результата обучения (чтобы оператор мог
  проверить модель) с оговоркой interpretation: оценка аномалии **не
  вероятность** и не имеет смысла «серьёзности».
- **Score a capture against the baseline** — выбор модели, лимит отчёта,
  галочки захватов, кнопка **Score captures**. Результат: бейджи по статусам и
  число сущностей в отчёте, график рангов (Recharts) и таблица «сущность /
  оценка / что повысило оценку / поток».
- Какой детектор активен, видно в JSON обучения (`algorithm`) и в ответе
  `/api/anomalies/status`: `isolation_forest`, если установлен `scikit-learn`,
  иначе `robust_profile` — честный numpy-профиль, о котором прямо сказано в
  предупреждении. Это не одно и то же: оценки двух разных базовых линий не
  сравниваются между собой.

### Формулировки от нейросети (внешний ИИ)

Выключено по умолчанию. Включается в `.env` (см. `.env.example`) и требует трёх
вещей: `MPLAB_ALLOW_EXTERNAL_AI=true`, настроенный эндпоинт и **согласие
конкретного проекта** в настройках проекта.

- Локально: `MPLAB_OLLAMA_URL` + модель (профиль compose `ai`).
- Хостинг: `MPLAB_LLM_BASE_URL` + `MPLAB_LLM_API_KEY` + `MPLAB_LLM_MODEL` — любая
  точка, отвечающая на `POST {base}/chat/completions` (OpenRouter, vLLM,
  LM Studio). Ключ живёт только в `.env`, который в git не попадает; ни одна
  страница, отчёт, лог и `/api/health` его не показывают.
- На хостинг уходит **только** обезличенные агрегированные выводы: байты
  пакетов, файлы захватов и ключевые журналы — никогда.
- Центр безопасности показывает это отдельной строкой: локальный эндпоинт =
  «проходит» (трафик не покидает машину), хостинг = «не проходит» с именем
  провайдера.

## 16. Investigation Assistant

Типизированный поиск по индексу. Модель **не выполняет код** — она переводит
фразу в план запроса, который исполняется безопасным движком.

- **Поле запроса** (до 1000 символов) с примером-подсказкой.
- Чекбоксы: **dry run (show the plan without executing)** — включён по умолчанию;
  **allow optional local model narration** — выключен по умолчанию.
- Кнопка **Run** (неактивна на пустом запросе).
- Результат:
  - при `needs_clarification` — панель **«The assistant refused to guess»**
    (бейдж, уточняющий вопрос, примечание, подсказки), то есть система лучше
    переспросит, чем угадает;
  - иначе **Result**: бейдж executed/planned, текстовое объяснение, план запроса
    (compiled query plan JSON), предупреждения, таблица результатов
    (id / stream / direction / range / length / entropy) и, если включена
    наррация моделью, отдельный блок.
- **Справа**: **Corpus** (чекбоксы захватов; без выбора — поиск по всему индексу),
  **What this can and cannot do** (execution_model, entities, бейдж внешнего ИИ,
  ограничения) и **Try one of these** — примеры запросов (клик подставляет).

Поле поиска в верхней панели ведёт сюда с уже заполненным `q`.

## 17. Reports

Генерация отчёта со ссылками на доказательства.

- В шапке: чекбокс **narrate with local model** и кнопка **Generate report**
  (голубая). Если наррация включена, а на сервере внешний ИИ выключен —
  появляется предупреждение.
- **Generated reports** — список отчётов (заголовок, дата, бейдж «AI used»).
- **Report** — панель с кнопками **Markdown** / **JSON** и текстом отчёта:
  заголовок, генератор, дата; предупреждение об ИИ, если применялся; секции
  (номер + заголовок, строки текста), **ссылки-доказательства** (клик ведёт в
  session / capture / hypotheses / settings; неподдерживаемые типы не
  линкуются) и примечания-оговорки.

> Кнопки **Markdown** и **JSON** открывают файл прямо с backend
> (`http://127.0.0.1:8010/api/reports/<report_id>/markdown` и `/json`) в новой
> вкладке.

## 18. Security Center

Честные проверки конфигурации, а не «зелёная галочка по умолчанию».

- Кнопка **Run configuration check** в шапке.
- Вкладки **Configuration checks** / **Audit log**.
- **Configuration checks**: сводка бейджей (pass/fail/unknown/na), блок Runtime
  (mode, bind, platform), список проверок (вердикт, название, id, детали,
  рекомендация при наличии), блок Integrations (имя, доступность, примечание) и
  **Documented limits** (список + оговорка о границах применимости).
- **Audit log**: **Audit chain integrity** (цепочка проверена/нарушена +
  пояснение; chaining обнаруживает изменение, но не предотвращает его) и таблица
  **Security events** (Time, Action, Outcome, Risk, Object).

Вердикт `unknown` — честный ответ там, где проверить нельзя (например, внутри
контейнера).

## 20. Легенды: цвета, тона, классы

Статус **никогда не передаётся только цветом** — у каждого бейджа есть текстовый
ярлык (требование доступности).

**Тона бейджей** (`StatusTone`): `ok` (зелёный), `warn` (жёлтый), `bad`
(красный), `info` (синий), `unknown` (серый), `neutral`.

**Классы байтовых колонок** (Workbench) описывают **форму** столбца, а не смысл
поля:

| Класс | Значение |
|---|---|
| `constant` | один и тот же байт во всех сообщениях |
| `counter` | растёт от сообщения к сообщению (счётчик/идентификатор) |
| `enum` | небольшой набор значений (тип/код статуса) |
| `high_entropy` | высокая энтропия (случайные/сжатые/шифрованные данные) |
| `variable` | меняется без явной структуры |

**Цвета протоколов** (Network Graph): HTTP/1.x, HTTP/2, gRPC, WebSocket, MQTT,
DNS/TCP, TLS — каждому свой цвет; всё нераспознанное — серый
(`unknown`, `unknown_binary`, `length_prefixed_unknown`), чтобы непрошедшее
классификацию было видно как непрошедшее.

**Тепловая карта Diff**: похожесть 0→1 это красный → жёлтый → зелёный; синий
оттенок — рост, янтарный — уменьшение.

## 22. Частые проблемы

| Симптом | Причина и что делать |
|---|---|
| Красное `backend down` | Не запущен API. Выполните `cd backend && python -m app`. |
| Пустые таблицы | Не выбран захват или не выполнен анализ. Captures → Run analysis. |
| «Select at least one capture» при проверке правила | Корпус не заполнен вручную. Отметьте захваты в CorpusPicker. |
| Anomaly Detection не обучает модель | Корпус меньше 50 сущностей. Возьмите больше сообщений/сессий либо поднимите `max_samples`. |
| Кнопка **Score captures** неактивна | Не выбрана модель или ни один захват. |
| Внешний ИИ не появляется в Assistant | Нужны `MPLAB_ALLOW_EXTERNAL_AI=true` **и** эндпоинт в `.env` **и** согласие проекта. Смотрите строку «внешний ИИ» в подсказках помощника. |
| Кнопки Markdown/JSON в Reports не открываются | Убедитесь, что backend запущен; они открывают файл прямо с `http://127.0.0.1:8010`. |
| Ошибка 413 при импорте | Превышен лимит размера загрузки (см. LIMITATIONS). |
| Ненулевые hash mismatch(es) при импорте `.mplab` | Файлы архива не совпали с записанными SHA-256 — разбирайтесь до доверия результатам. |
